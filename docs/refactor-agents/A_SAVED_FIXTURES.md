# Saved fixture lifecycle completion

The seven remaining saved-family JavaScript modules now delegate to one strict
Node lifecycle implementation. A shared host facade wires existing process,
lineage, immutable-file, audit, invocation and SDK-proof adapters without creating
another persistence or admission implementation. The first-save publication
projection is pure Core policy. Explicit contracts describe owner approval,
folder creation/readback, epoch/job identity, grant scope, native receipt binding,
first-save result and separate publication observations.

No authorization is broadened. Source/build/owner binding, the exact five-artifact
administrative set, original readiness jobs, one first-save request, namespace
ownership, immutable marker-before-grant publication, separate native destination
observation and receipt-only replay all retain their existing decisions.
Retention still means keeping a new qualification file for user inspection; it
never grants permission to change or delete existing user data.

## Historical evidence

All seven source fixtures are byte-identical to GitHub baseline `330849f` and the
immediate predecessor. Their SHA-256 hashes are pinned in the historical manifest.
`tests/contracts/saved-lifecycle-migration.test.ts` runs identical inputs through
those sources and the typed implementation, using the same explicit synthetic
host ports and real temporary JSON artifacts. The five scenarios cover:

- Exact owner approval, readiness records, administrative artifact hashes and
  observed native destination; foreign owner/job and altered proof refusal.
- First-save grant/admission, exact request/destination arguments, two immutable
  writes and idempotent receipt-only replay without another write.
- Accepted versus completed publication, processing/missing/error readback,
  exact new-file lineage, foreign-file refusal and version drift.
- Original-owner control, legacy receipt replay and CLI control fencing without
  preparing another SDK attempt.
- Complete nine-artifact first-save evidence, checked physical receipt binding,
  independent publication observation and foreign postflight-document refusal.

These ports describe synthetic terminated workers and settled evidence; they do
not qualify a real process, cloud project or Fusion save. Existing physical
saved-family suites and generated Python admission remain mandatory CI/native
obligations. The production process and ownership guards are unchanged.

## Validation

Strict workspace build, strict test types, formatting, adapter/Core lint, and all
nine combined saved proof/lifecycle historical tests pass locally. Public module
exports remain compatible. The new test is handed to G for full regression
registration; no shared workflow or package script is changed by this delivery.

The shared host composition is also strict TypeScript in
`src/composition/library-saved-runtime.ts`; `queue-saved-runtime.js` is only its
installation-anchor facade. The existing library-composition compiler glob and
stager include it without a new unchecked JavaScript orchestration module.
