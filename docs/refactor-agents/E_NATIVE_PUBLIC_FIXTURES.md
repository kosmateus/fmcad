## Owned exports

`native-file-export-cases.ts` uses the existing ScenarioSession, canonical CAD
commands, exclusive instance barrier and default ten owners. The runner owns
creation, SDK serialization, exact unsaved identity, final closure and foreign
inventory/active restoration. The case retains a 10×20×30 mm box, root STEP,
STEP reimport/BRep comparison at 0.001 mm, body STL at 0.1 mm surface deviation,
two explicit parts with atomic:false, all four actual binary lengths/hashes and
the STEP ISO-10303-21 header. Mapped local bytes must match the Fusion readback.

The output location deliberately changes from the global Fusion temporary
directory to each durable scenario's private directory. Every native path must
be absolute and preserve the exact immediate parent and owner-derived basename.
The case proves all paths absent before exporting; a foreign existing path is
never adopted or removed. Known settled failures still clean verified owned
files. Unknown mutation/receipt, changed owner or unverifiable cleanup preserves
the fixture/files and latches a durable cleanup hold without replay.

The retained script calls `validated('export.verify')` three times despite only
one invocation. After the first call marks it passed, the next necessarily
throws before binary readback. The factory keeps both original reimport/BRep
assertions and validates that invocation once. This fixes bookkeeping, not an
expected geometry result. Frozen source remains unchanged for comparison.

Offline safety tests exercise real simulator metadata and owner lifecycle on
both MCP and add-in profiles, inject a nested incomplete outcome before any CAD
or file command, and verify retained identity, durable hold, blocked next owner
and recovery without replay. Unsupported capabilities create no fixtures and
send no SDK requests. These checks do not simulate STEP, tessellation or BRep
reimport. Strict compilation and ESLint pass; their execution remains pending this
batch's coordinated runtime slot.

## Fixed GM07 and GM12

The existing fixed Python programs, manifests, hashes, helper methods and native
grants remain unchanged. Their drivers now use the shared native invocation
intent helper from `live-import-receipts.ts`: an exclusive fsynced per-request
record of command, owner document/client, installed build/source and driver
PID/birth exists before spawning. This record is independent of the summary
report that a later run may overwrite. The shared stable native-invocations
directory also retains a one-shot fixture/document claim across processes; a
new random request ID does not authorize replay after an unknown outcome. Accepted and terminal request/job/client
identity and settled outcome must match. Missing, duplicate, malformed or
foreign receipts leave the original intent unqualified and stop without retry.

A CLI terminal observation is distinct from independent original-worker
recovery. The existing helper only queries the original request after proving
the original driver dead; it never submits work, retries a mutation or closes a
document. GM12 retains externally owned scratch semantics; GM07 keeps its exact
pristine scratch, guarded close and restoration. Native readiness still needs
actual final build qualification and the unchanged fixed-source observations.

The new local tests execute the actual retained `runFixedProgram` function bytes
with a synthetic child-process port. They inspect the real persisted intent
before that port is entered, and cover child failure, foreign client/request/job,
duplicate acceptance, malformed terminal and missing native payload. This tests
admission plumbing, not the fixed Python's Fusion result. Strict compilation and ESLint pass. Runtime is pending; readiness labels
remain conservative until those checks pass.
