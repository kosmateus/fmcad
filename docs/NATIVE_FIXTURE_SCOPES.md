# Fresh owned scratch and typed native fixture scope

The basic smoke grant is unchanged. It cannot execute arbitrary Python, create
another document, save a file or expand into a broader native suite by changing
a runner flag. The regional qualification uses a separate, explicit owner grant
and the same typed public API, broker gate, Python checker and physical queue.

## Closed-scratch succession

Before a new fixture document, the original owner must complete the fixed
`close-isolated-scratch` operation for the exact previous epoch/document. Its
`closed.json` marker alone is insufficient. The new reader verifies the original
intent, checked start, wire, durable SDK close proof, independently bound terminal
physical receipt and exact active-document restore requirement. Missing, failed,
pending, altered or foreign evidence fails closed.

`authorize-closed-successor` is metadata-only. It requires the original owner,
the same live Fusion process and broker, zero active/leased/unknown work, a pinned
current runtime and installed qualification with `closedEpochSuccessorQualified`.
Its separate approval purpose is `closed-isolated-epoch-successor-v1`, with exact
`requestId`, `clientId`, `epochId`, pointer/state/closed-proof hashes, current
source/build and a hashed qualification reference. This route does **not** claim
that the prior process died and does not copy any grant.

```text
fmcad queue authorize-closed-successor --request-id RUN --succession-approval /private/approval.json --confirm-ownership true
fmcad queue observe-successor --job ORIGINAL_TARGET --observation-job ORIGINAL_OBSERVER --request-id RUN:observe
fmcad queue create-isolated-scratch --job ORIGINAL_TARGET --observation-job ORIGINAL_OBSERVER --request-id RUN:create
```

The observation and creation reuse fixed, source-bound sources. Creation is
unavailable before a known current-facts receipt. It creates one genuinely new,
empty, independent, unsaved document and captures the previously active document.
The old stores, jobs, grants and cleanup evidence remain immutable lineage.
An unconsumed authority fences other request IDs. Lost ACKs are observed under
the same IDs; they never authorize another SDK creation.

The original live owner is part of the pending authority's fence. This initial
closed-successor route does not authorize arbitrary broker takeover after a
pending operation loses its owner. Retain its journal/unknown outcome; never
delete guards or mint a new request as a recovery shortcut.

## Regional typed grant

The owner grants only a separately registered fixture client, on that new epoch
before any managed model work. An existing basic grant is never broadened or
replaced in place:

```text
fmcad queue grant-native-fixture --epoch-id EPOCH --grant-client CLIENT --fixture-id regional-geometry-v1 --request-id GRANT_REQUEST --confirm-ownership true
```

The grant pins source/build, exact document/client/epoch and SHA-256 of the
installed `assets/native-qualification/regional-geometry.json` manifest. Only
that fixture's registered transactional typed operations are admitted. Raw/run,
nested batches, other documents, input files, save/export and cloud effects are
not part of this authority. A changed runtime or manifest does not implicitly
promote the old fixture scope.

Each isolated physical RPC also carries an exact document guard before its model
body executes: the one creationId/name must still identify a valid unsaved,
unlinked document. An external save, rename or reference addition is not covered
by the old request pins. The nullable `dataFile` getter is represented using the
same narrow contract as the qualified scratch proof, not by disabling checker
diagnostics. Installed qualification covers 27 fixed-source/modeling artifact
classes, including the regional primitives, comparison, snapshot and this guard.

This is an **operation scope**, not attestation of arbitrary client program
bytes. The manifest describes the fixture, but a client can choose data within
its approved typed operations. The safety boundary is the exact owned document,
registered operation subset and shared broker—not a Python sandbox or a claim
that client code cannot be modified.

## Fixed containment program

`containment-program-v1` is a distinct source-pinned alternative, not general
`run` permission. The grant binds the installed containment program's exact
canonical path/SHA-256, its manifest, `cad-v1` helper, current runtime, client,
epoch and creationId. Admission accepts one source input only and the four
declared arguments: approved opt-in, exact creationId, current Fusion version
and a bounded uppercase fixture prefix. Other sources, helper exceptions,
extra inputs, output paths and arbitrary arguments are refused. A fixed-program
client cannot use its grant for unrelated catalog operations.

The program reuses the existing run/helper/checker pipeline and the retained
native containment fixture. It creates one box only in its proven-new owned
document, then measures the declared inside/outside/boundary points. It cannot
create/open/close/save documents or write files/cloud data. Caller cleanup and
restore are separate. The actual helper's `doc`, `design` and `root` members have
narrow SDK declarations; unsupported members remain checker errors. No checker
diagnostics are disabled, and stub-only typing modules are not imported in Fusion.

Successful, SDK-settled typed `document.status`/`snapshot` readiness queries on
that exact new document do not count as model writes. This permits validating
the fresh document and performing a qualified runtime handoff before issuing a
new fixture grant. Mutating, failed, unknown, unscoped or unfinished jobs still
refuse fresh fixture authority, and the program itself checks native freshness
again before its first mutation.

## Fixed section/witness program

`sections-program-v1` is a separate exact source/hash grant. It retains the
geometry and required cases from `tests/native/section_witness_qualification.py`
and `tests/fixtures/section_witness_shapes.json`, rather than changing the
production comparator or substituting point samples for finite witness solids.
The caller pins the actual qualified current Fusion version; the historical
2706.1.14 fixture pin is not a qualification claim for a later build.

The fixture creates rings, cutters and witness solids only in its own fresh
document. It checks material/void positive and negative cases, missing angular
sector and axial gap, closed annulus/C-shaped sections, transient native open
wire face rejection, mismatched-frame rejection and expected unknown empty or
tangent intersections. Discrete stations remain partial coverage. Body counts,
timeline and document flags are compared around evidence operations. Caller
cleanup/restore remains separate, and script/checker success is not native PASS.

## Fixed sketch geometry proof

`sketch-proof-program-v1` retains the five sketch fixtures and twelve cases in
the existing deferred typed sketch plan. Unlike that restricted plan, its exact
program invokes the registered `sketch.coordinate-check` on the actual created
circle reference, including positive coordinates and negative center/diameter
expectations. Health, native coordinate evidence and sampled profile evidence
are independent results; healthy sketches do not imply correct geometry.

Native profile enumeration includes both the inner disk and the annulus for
two concentric circles. The explicit expected aggregate counts are two profiles,
three loops, two outer loops and one inner loop. A unique annulus query must
still match the annular material and reject its void; ambiguity or incomplete
topology never authorizes a first-profile fallback. Sampled containment/topology
must retain `sampled` precision and `partial` evidence, not an exact certificate.

Native evaluator stroke endpoints at a closed circle seam may differ by tiny
floating-point residuals. Sampled containment includes seam segments only for
unambiguous endpoint pairs within the existing stroke tolerance, so a ray cannot
double-count that seam. Open/branched or unmatched boundaries remain unknown;
the boundary-distance band is still unknown. No model curves or input samples
are modified, no tolerance is loosened, and the result remains sampled/partial.

The same bounded arguments, exact source/hash/doc/runtime grant and caller-owned
cleanup rules apply. A sketch fixed-program grant does not grant arbitrary
sketch operations, other fixtures, file/cloud effects or document lifecycle.

## Fixed measured fasteners

`measured-fasteners-program-v1` retains the axial datum geometry from the
integrated measured-fastener fixture. Native measurements, source provenance,
frame and coverage are checked separately from declared catalog lengths. The
eight cases cover baseline engagement, contradictory declaration/native evidence,
bottoming, short engagement, misaligned axes, missing measurement and unchanged
model/save state. Root-native datum entities use the retained assembly frame
contract, not child-component-local coordinates.

The metric carries measured status/sourceVersion; its `provenance` array contains
direct source records with sourceRef/sourceVersion/frame/documentIdentity, not
nested measurement objects. Fixture validation uses the real evaluator shape and
refuses incomplete, foreign-document or incorrectly nested provenance. Completed
helper calls alone are never treated as a native qualification report.

All datum fixtures are created before the evidence baseline. Counts, timeline
and document flags are compared around all five native measurement calls, not
merely around a final status read. No thread BRep, load/force capacity or physical
fastener/manufacturing qualification is claimed. Exact program/hash/arguments,
owned unsaved document, no file/cloud effects and separate caller cleanup apply.

## Shared fixed Drive/MotionLink fixture

`drive-motion-program-v1` shares one fresh owned assembly for the two native
features. Its immutable contract is ratio 1:1 and zero phase, not values inferred
from the link being tested. It reads actual native driver/follower joints,
detects a disconnected follower, creates and reads back a native MotionLink,
then measures positive solver behavior and negative ratio/phase expectations.

Each drive call must report a known successful restore before the next fixture
mutation. Unknown/failed restoration or unproven link creation returns partial
evidence and stops; no automatic retry or cleanup can certify that state. The
fixture does not inject restore failures or claim body-proxy/load qualification.
Native Joint references retain their SDK kind spelling. Resolution follows the
existing typed `joint.inspect` handler, which supports Joint and AsBuiltJoint
(the default revolute factory creates AsBuiltJoint). The fixture checks the
returned native kind, RevoluteJointMotion, finite rotationValue and cm/rad units
before actuation. It does not duplicate an incorrect Joint-only SDK class guard
or invent a lowercase expected-kind alias.

The coupling fixture uses a fixed one-degree waypoint grid (half-degree driver
steps for the wrong-ratio control), retaining driver/restore tolerance 1e-6 rad
and follower tolerance 1e-5 rad. The original off-grid 0.05-rad run remains a
native tracking FAIL: live angles landed on a 0.1-degree lattice, despite exact
driver/follower coupling. Grid qualification does not certify arbitrary-angle
setter precision or identify which native stage imposes that quantization.
It cannot create/open/close/save documents or write files/cloud data. Its grant
does not authorize general assembly operations or caller-controlled ratio/phase.

## Fixed coordinate precision diagnosis

`drive-precision-program-v1` creates only two fresh empty components, grounds the
base and creates one native revolute joint. Its three fixed targets are 0.05 rad,
0.1 rad and one degree. Each is driven once, observed, restored once to zero,
and independently checked by joint inspection and all occurrence matrices.
Unknown/failed restore stops subsequent trials. The program cannot create links,
set followers, write native SDK properties directly, or affect documents/files/cloud.

`joint.drive` exposes `coordinateReadback.evaluated` (the expression evaluator's
numeric result) and `coordinateReadback.beforeCapture` (actual native properties
after setters, before existing position capture). Existing top-level coordinate
fields remain actual post-capture reads. These observations neither retry writes
nor normalize or hide quantization. The diagnostic never claims precision or
coupling qualification merely because its SDK program completed.

## Saved destination and identity prerequisites

`queue-saved-destination-approval` validates explicit original-owner approval,
the new folder creation intent/result and an independent folder readback. It
does not issue a grant or save a file. Workspace API project IDs are not silently
treated as SDK DataProject IDs. The approved retention is to keep new test files
for user inspection; changing existing data, permissions or deleting test files
is outside this approval.

The receipt wrapper has a separate `auditExpectedSavedDocument` guard, only for
`saved-fixture-modeling-v1`. It requires exact name/creationId/fileId/projectId/
folderId/version, a saved complete DataFile and no document references. Mixed
saved/unsaved guard bindings are rejected. The existing unsaved guard is unchanged
and still refuses saved files. Neither this guard nor its installed checker
certificate is authority to bypass admission or convert an existing scratch
grant into save permission.

`document.save_as` supports optional `expectedProjectId` and `expectedFolderId`
pins in addition to the existing exact project/logical-path selector. Different
native IDs, including a folder replacement at the same path, refuse before
saveAs. Omitting the pins preserves the retained contract. First-save scope
requires the separately verified native destination and binds one stable request
ID, exact newly created document/name and both IDs; arbitrary CAD/file/run work
or conversion of an existing client grant is refused.

A saved first-save/publication/retention lifecycle must be independently wired
and qualified before use. `savedFixtureDocumentGuardQualified` certifies only
the final-byte checker path, not that broader lifecycle or native saved modeling.

The fixed administrative destination/publication/retention reader sources are
separate artifact classes. The destination probe reads actual SDK project/hub IDs
and the approved folder ID without changing the active hub or saving anything.
Publication observations never resubmit saveAs. Retention refuses dirty,
incomplete or version-drifted files before its sole UI close; it preserves the
cloud DataFile and restores only the captured active-document identity (or keeps
a different user-selected active document). An immutable retention intent blocks
another close request after an uncertain result. These reader certificates do
not themselves issue saved modeling grants. See `SAVED_FIXTURE_LIFECYCLE.md`
for the public owner actions and the distinct publication/retention boundaries.

Authenticated helper stages use the current admission epoch's QueueState and
runtime identity, while retained accepted bytes, job directories and physical
receipts remain under the shared broker root. Changing the selected epoch
invalidates stage ownership; a missing/pending or foreign snapshot is not a
reason to fall back to root history. An unsaved helper document may have a null
fileId only when the exact physical preflight proves it is unsaved. Saved-file
workflow pins retain their existing requirements.

Helper, batch and save stage consumers retain preflight-first execution through
the existing broker worker path. They cannot prepare authenticated stage context
in an offline worker before physical preflight exists. Ordinary typed CAD keeps
its parallel offline preparation. Neither path bypasses Python admission, the
shared SDK gate or physical receipt validation.

## Public API fixture driver

`tests/native/integrated-qualification/regional_typed.js` uses only public
`FmcadServices`. Its caller supplies the actual grant, stable run ID, canonical
manifest/evidence paths and exact current document/source/build/client pins.
It does not create, adopt, activate, close or restore documents.

Before fixture mutation it reads native status and snapshot and refuses a saved,
modified or nonempty scratch. Seven native bodies cover the original positive,
outside-mask, equal-volume, exclusion, overlapping masks, hole and protected
precedence cases. The equal-volume pair is independently measured as 400 mm³.
Native snapshots, timeline and saved/modified flags are compared around the
temporary-copy measurements. Native `unknown` remains `UNKNOWN`, never PASS.

Expected negative controls retain the CLI/API's real `failed` worker outcome.
The test harness accepts them only as complete, document-bound regional
diagnostics: native precision/coverage, source provenance, consistent finite
volume partitions, controls and expected added/removed volumes must agree.
It never rewrites a failed receipt to succeeded or accepts a generic execution
error as a valid negative test. Late output is observed through the same job;
unknown reconciliation evidence is retained separately from a final result.

The retained measurement contract expresses native root bodies in the
**assembly** frame, even without an occurrence. `component local` is for native
child-component coordinates and is not interchangeable with root assembly.
Regional result identity publishes name/file/version/modified fields; exact
creationId remains pinned in the request and physical broker document guard.
The driver does not invent a mandatory creationId result field. If an earlier
read used the wrong frame, corrected observations receive distinct request IDs
and the original unknown receipts remain referenced, never rewritten as PASS.

Every phase publishes a send intent before one submit. A lost ACK is recovered
only through the same owned request/job. Independent parallel phases are all
observed to settlement even when one fails; no SDK work is resubmitted. Completed
phase receipts are reused on a resumed run. An intent without observed acceptance
is an explicit unknown, not permission to try another execute.

The driver is currently an explicit public-API entrypoint; it does not silently
replace the historical trusted Python runner in the integrated manifest.
Full integration and live evidence must be completed before reporting the group
as qualified. Its FAKE API tests are not Fusion proof. Owner cleanup/restore is
separate and remains mandatory; neither a checker PASS nor native kernel volume
is manufacturing or physical-world validation.
